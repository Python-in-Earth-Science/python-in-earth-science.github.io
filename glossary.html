Course Glossary

Key terms and definitions for the tools and concepts we use in this class. This document lives in the course-materials repository and will be updated throughout the semester.

Version Control
Git version control

Software that tracks changes to files over time, so you can see what changed, when, and by whom — and recover older versions if needed. It's the tool that makes collaborative code possible without people overwriting each other's work.

GitHub version control

A website that hosts Git repositories in the cloud. Think of it as the online storage location for code and files. Our class repository lives at github.com/Python-in-Earth-Science/course-materials.

Repository (repo) version control

An organized collection of files and folders that Git is tracking. You can think of it as the class "filing cabinet" — Dr. Morey adds notebooks and datasets to it, and you pull copies to your own ExploreHub.

Pull version control

Downloading the latest version of files from a remote repository to your local machine or JupyterHub. When you click "Week N materials" on the course website, nbgitpuller is doing a pull behind the scenes.

Push version control

Uploading your local changes to a remote repository. This is what Dr. Morey does when adding new course files — you won't need to push anything until later in the semester.

Commit version control

A saved snapshot of changes in a Git repository, accompanied by a short message describing what changed. Commits are how Git keeps a history of a project over time.

Version control version control

A system for tracking and managing changes to files over time. It lets you see what changed, when, and why — and roll back to earlier versions if something breaks. Git is the most widely used version control system in science and software development.

upstream version control

Dr. Morey's original version of course-materials/ on GitHub, as opposed to the copy pulled onto your ExploreHub. When nbgitpuller updates a file, it's pulling the upstream version — if you've edited a file with the same name, nbgitpuller renames your copy with a timestamp rather than overwriting it.

Computing Environment
JupyterHub environment

A shared server that lets multiple users run Jupyter notebooks without installing anything on their own computers. Everyone logs in through a browser and gets their own private space with Python and all necessary packages pre-installed.

ExploreHub environment

The specific JupyterHub this class uses, hosted by CSDMS (Community Surface Dynamics Modeling System). Access it at explore.openearthscape.org. This is where you'll open and run all your notebooks.

JupyterLab environment

The interface you see when you log into ExploreHub — the file browser, tabs, menu bar, and notebook editor are all part of JupyterLab. It's the application running on top of the JupyterHub server.

CSDMS environment

Community Surface Dynamics Modeling System — the organization that runs the ExploreHub server. CSDMS promotes open software tools and protocols for earth-surface process modeling.

Kernel environment

The engine running behind the scenes that reads your code and actually executes it — when you click "run," the kernel is what does the work. Always select CSDMS when opening a notebook in this class, unless told otherwise.

interpreter environment

A program that reads and runs code one line at a time, rather than translating the whole program before running it. The kernel in a Jupyter notebook is an interpreter running behind the scenes.

compiler environment

A program that translates an entire program into machine-readable instructions before it runs, all at once. Python is not compiled this way — it's interpreted — but languages like C++ use compilers.

Notebooks & Files
Jupyter Notebook (.ipynb) files

A file that combines written text, code, and the outputs of that code all in one document. The .ipynb extension stands for "interactive Python notebook." This is the main file format for this class.

Markdown cell / Code cell files

The two building blocks of a Jupyter notebook. A Markdown cell renders formatted text, headings, and equations; a Code cell executes Python. Both are run with Shift + Enter.

pathlib / Path files

A Python module for working with file paths as objects instead of plain strings. A Path object (e.g. Path.home()) handles the / vs \ difference between operating systems automatically and has built-in methods like .exists(), .stem, and .parent.

File path files

The address that describes where a file lives in a folder structure, like /course-materials/week01/demo.ipynb. Understanding file paths is essential for loading data in Python — the computer needs to know exactly where to look.

nbgitpuller files

A tool that connects JupyterHub to a GitHub repository. When you click a "Week N materials" button on the course website, nbgitpuller automatically pulls the latest files from GitHub and places them in your ExploreHub account — no manual steps needed.

absolute path files

a file address starting from the root of the file system (e.g. /home/susannah/...)

relative path files

a file address relative to the current working directory (e.g. ./data/input.csv)

directory files

synonym for folder; the term used in programming/terminal contexts

current working directory files

the folder Python is currently "in"; returned by os.getcwd()

root directory files

the very top of the file system (/)

hierarchical file system files

the tree structure computers use to organize files and folders

Python Basics
module python basics

A file containing Python code that can be imported and used in other Python files. A collection of related functions and tools you import before using (e.g. os, pathlib)

function python basics

A reusable block of code that performs a specific task. Defined using the `def` keyword. When called, a function does something (e.g., os.listdir())

dot notation python basics

The syntax used to access a function inside a module or the attributes and methods of an object in Python (e.g., os.getcwd())

string python basics

A sequence of characters in Python, enclosed in single or double quotes (e.g., "Hello, World!")

comment python basics

A line of text in Python code that is ignored by the interpreter. Used to explain or annotate code. Starts with a hash/pound symbol (#).

command mode / edit mode python basics

Jupyter's two states; Esc enters command mode, Enter enters edit mode

variable python basics

A named location in memory that stores a value. Created with an assignment statement (e.g. x = 5) and can be reused or changed later in your code.

snake_case python basics

Our course convention for naming variables: all lowercase, with words separated by underscores (e.g. age_ma, sample_count).

object python basics

In Python, everything is an object — an entity that holds data along with associated metadata and functionality, such as a type. A variable name is just a pointer to an object; the object carries the type information, not the name.

assignment operator python basics

The single equals sign (=) used to assign a value to a variable. Not the same as the mathematical "equals" — x = 5 means "store 5 in x," not "x equals 5."

operator / operand python basics

An operator tells Python to perform an operation (e.g. +); the operands are the values it acts on. In 3 + 4, + is the operator and 3 and 4 are the operands.

arithmetic operators python basics

Operators that perform math: + - * /, plus three that are easy to forget — // (floor division, true division with the fractional part truncated), % (modulus, the remainder after division), and ** (exponentiation, e.g. 11**2).

comparison operators python basics

Operators that compare two values and return True or False: == != > < >= <=.

update operators python basics

Shorthand operators that combine an arithmetic operation with reassignment, e.g. a += 2 is equivalent to a = a + 2. Also available: -= *= /= //=.

data type python basics

The category of value a variable holds — such as a whole number, decimal number, or string of text. Python determines a variable's data type automatically based on the value assigned to it.

int / float python basics

int is a whole number (e.g. 7); float is a number with a decimal point (e.g. 7.0). Python treats these as different data types even when the value looks the same.

bool python basics

A data type that holds only two possible values: True or False. Usually the result of a comparison, e.g. age_check = age_ma >= 61.

type() python basics

A built-in function that returns the data type of whatever you pass it (e.g. type(3.14) returns float). Useful for checking your assumptions about a variable.

type casting python basics

Converting a value from one data type to another using a built-in function: int(), float(), or str() (e.g. int(3.14) returns 3). Different from type(), which only checks a data type rather than changing it.

reassignment python basics

Giving a variable that already exists a new value (e.g. x = 5 followed later by x = 10). The old value is overwritten — Python does not keep a record of it.

f-string python basics

A formatted string literal — written as f"..." — that lets you insert variable values directly inside a string using curly braces (e.g. f"The velocity is {v} cm/yr").

attribute python basics

A piece of data stored inside an object, accessed with dot notation and no parentheses (e.g. path.suffix). Contrast with a method, which does something rather than just holding a value.

method python basics

A function that belongs to an object, accessed with dot notation and called with parentheses (e.g. planet_list.append("Saturn")). Contrast with an attribute, which stores data rather than performing an action.

parameter python basics

A named input a function or method is built to accept, listed inside its parentheses when defined (e.g. the key in planet_data.get(key)). The actual value you pass in when calling it is the argument.

built-in function python basics

A function that is always available in Python without importing anything — e.g. print(), len(), type(), sum(), range(), zip(), and enumerate(). Functions that live inside a module (like math.sqrt()) need an import first.

len() / sum() / min() / max() / abs() python basics

Built-in functions for summarizing numbers and collections. len(x) counts the items, sum(x) adds them up, and min(x) / max(x) find the smallest and largest. max() and min() also work on separate values — max(0, -3.2) gives 0, a compact way to keep a value from going below zero. abs(x) drops the minus sign.

end (print argument) python basics

An optional argument to print() that sets what gets printed after the text. The default is a new line; print("*", end=" ") uses a space instead, so the next print continues on the same line. A bare print() just starts a new line, which is how a nested loop can finish a row.

floating-point error python basics

Computers store decimals in binary, so numbers like 0.1 can't be represented exactly. Tiny errors add up when you repeat an operation: adding 0.1 ten times gives 0.9999999999999999, not 1.0. That's why we count with range() (exact whole numbers) and divide fresh each time, instead of building decimals by repeated addition.

Functions
function functions

A reusable block of code that performs a specific task. Defined using the `def` keyword. When called, a function does something (e.g., os.listdir())

module functions

A file containing Python code that can be imported and used in other Python files. A collection of related functions and tools you import before using (e.g. os, pathlib)

dot notation functions

The syntax used to access a function inside a module or the attributes and methods of an object in Python (e.g., os.getcwd())

positional argument functions

An argument matched to a function's parameter by its order in the call, not its name — e.g. in blackbody_temp(1360, 0.31), 1360 fills the first parameter and 0.31 fills the second, whatever they're named.

keyword argument functions

An argument matched to a function's parameter by name rather than order — e.g. blackbody_temp(a=0.31, S=1360). Order doesn't matter once you use keyword arguments.

default parameter value functions

A fallback value assigned to a parameter in a function's definition (e.g. stef_boltz=5.67e-8), used automatically whenever the caller doesn't supply that argument.

docstring functions

A triple-quoted string placed as the first line inside a function, documenting what it does, its parameters, and what it returns. Displayed by Python's built-in help() function.

help() functions

A built-in function that displays another function's docstring and parameter list — works on functions you wrote yourself and on functions from any module (e.g. help(math.sqrt)).

dir() functions

A built-in function that lists everything (functions, constants, etc.) available inside a module — useful for browsing an unfamiliar module, e.g. dir(stats) after import statistics as stats.

local scope functions

A variable created inside a function exists only inside that function — once the function returns, the variable disappears and can't be accessed from outside.

global scope functions

A variable defined outside every function exists for the rest of the notebook and can be read by any function defined afterward, without needing to be passed in as an argument.

singleton (tuple) functions

A one-item tuple, written with a trailing comma: (5,). Without the comma, (5) is just the integer 5 in parentheses, not a tuple — an easy gotcha when a function returns exactly one value wrapped this way.

Control Flow
if / elif / else control flow

The keywords used to branch code execution based on a condition. if runs a block when its condition is True; elif ("else if") checks another condition if the previous ones were False; else catches whatever's left.

logical operator (and / or / not) control flow

Keywords used to combine or invert conditions. and is True only if both conditions are true; or is True if either is true; not inverts a condition (True becomes False and vice versa).

membership operator (in / not in) control flow

Tests whether a value exists (in) or doesn't exist (not in) inside a list, string, or other collection — e.g. "severe" in burn_severity.

nested if statement control flow

An if statement written inside another if statement's indented block, so the inner condition is only checked once the outer condition has already been met.

ternary operator control flow

A one-line shorthand for a simple if/else that assigns a value: x = a if condition else b. Functionally identical to the full if/else form, just more compact.

pass control flow

A keyword that does nothing — used as a placeholder to keep a code block syntactically valid while it's still being written (e.g. an empty if-block).

loop / iteration control flow

Code that repeats. Each trip through a loop's indented block is one iteration (or "pass"). Python has two kinds of loops: while loops and for loops.

while loop control flow

A loop that repeats as long as a condition stays True. Useful when you don't know in advance how many repeats you'll need (e.g. while rw < 1.0:). You are responsible for changing something inside the loop that will eventually make the condition False — otherwise you get an infinite loop.

for loop control flow

A loop that runs once for each item in a collection — a list, a dictionary's items, a range, and so on: for rw in rw_values:. When it runs out of items, the loop is done.

loop variable control flow

The variable a for loop creates to hold the current item on each pass, e.g. rw in for rw in rw_values:. Its name is up to you, so pick one that says what it holds. It hands you the value, not its position in the list.

iterable control flow

Anything a for loop can go through one item at a time: a list, tuple, string, range, or the result of .items(), zip(), or enumerate().

infinite loop control flow

A loop that never stops because its condition never becomes False — usually a forgotten update line in a while loop. It isn't an error message; the cell just keeps running. Click the ■ (interrupt kernel) button in the toolbar, then clear the cell's output.

count-controlled loop control flow

A loop whose number of repeats is fixed before it starts, such as for i in range(11): (exactly 11 passes). Contrast with a while loop, which repeats until a condition changes.

range() control flow

A built-in function that produces a sequence of whole numbers. range(5) gives 0, 1, 2, 3, 4 — it stops before the number you give it. range(start, stop, step) lets you choose where to begin and how big each step is, e.g. range(5, 50, 5) gives 5, 10, ..., 45.

zip() control flow

A built-in function that pairs up items from two (or more) lists by position, so a loop can walk through them together: for c, fs in zip(cohesion_values, fs_values):. It stops at the shortest list. Combine it with dict() to build a dictionary: dict(zip(keys, values)).

enumerate() control flow

A built-in function that gives you each item's position and value together: for i, x in enumerate(my_list):. Positions start at 0. It replaces a manual position counter.

break control flow

A keyword that immediately exits the loop it sits in. In a nested loop it exits only the innermost loop — the outer loop carries on with its next item.

continue control flow

A keyword that skips the rest of the current pass and jumps straight to the next pass of the loop. Useful for skipping items you don't want to process, such as a missing value.

nested loop (outer / inner loop) control flow

A loop inside another loop. For each pass of the outer loop, the inner loop runs all the way through and then starts over. The innermost line runs (outer passes) × (inner passes) times.

counter / accumulator control flow

A variable that starts at a value (usually 0) and is updated on each pass of a loop to keep a running count or total, e.g. total += x or count += 1. If it should start fresh for each item of an outer loop, create it inside the outer loop, before the inner loop.

flag variable control flow

A True/False variable that remembers whether something happened inside a loop — e.g. found = False, set to True when a match turns up. After the loop, if not found: lets you tell that the loop finished without finding anything.

sentinel value control flow

A placeholder value that means "nothing yet." Setting previous = None before a loop and checking if previous is None: lets you handle the first pass, when there is no previous item to compare against.

running maximum ("best so far") control flow

A pattern where a variable holds the largest (or smallest) value seen so far and is updated whenever the loop finds a better one, often along with the item that produced it. Start it at a value that is guaranteed to be beaten, like 0 or None.

Data Structures
mutable / immutable data structures

A mutable object can be changed in place after it's created — lists and dictionaries are mutable. An immutable object cannot — ints, floats, strings, and tuples are immutable; any "change" actually creates a new object.

.insert() data structures

A list method that inserts an item at a specific index, shifting later items over to make room — modifies the list in place. E.g. months.insert(6, "July").

.copy() data structures

A list method that returns a new, independent list with the same values — use it instead of plain = when you want a separate copy rather than another name for the same list (see aliasing).

identity (== vs. is) data structures

== checks whether two things have the same value. is checks whether two things are the exact same object in memory. Two separately-created lists can hold identical values (== is True) while still being two different objects (is is False).

aliasing data structures

When two variable names point to the same mutable object rather than separate copies of it — e.g. list_b = list_a does not create a new list, it just gives the existing list a second name. Changing list_b will also change list_a. Use .copy() when you want an independent list instead.

nested list data structures

A list whose elements are themselves lists (e.g. [[1, 2], [3, 4]]). Useful for representing table-like or grid-like data.

matrix-style indexing data structures

Accessing an element of a nested list with two sets of square brackets — outer_list[row][col] — the first bracket picks the inner list, the second picks the element within it.

tuple data structures

An ordered, immutable collection of values, written with parentheses (e.g. (37.87, -105.32)). Once created, its contents can't be changed — commonly used for fixed pairs like coordinates.

tuple unpacking data structures

Assigning each element of a tuple to its own variable in a single line (e.g. lat, lon = site_coords). The number of variables on the left must match the number of items in the tuple.

dictionary data structures

A mutable collection of key–value pairs, written with curly braces (e.g. {"Earth": 5.97e24}). Values are looked up by key rather than by position, so order doesn't matter for retrieval.

key / value data structures

The two parts of each dictionary entry: the key is the label used to look something up (must be unique and immutable, e.g. a string); the value is the data stored under that key (can be anything, including another dictionary).

.append() data structures

A list method that adds an item to the end of a list: fs_values.append(fs). Usually paired with an empty list (fs_values = []) that a loop fills up one item at a time.

.index() data structures

A list method that returns the position of the first matching item: [10, 20, 30].index(20) gives 1. Raises a ValueError if the item isn't in the list.

.sort() data structures

A list method that sorts the list in place — it changes the list itself and returns nothing: my_list.sort().

.pop() / .remove() data structures

Two ways to take an item out of a list. .pop(i) removes the item at position i and gives it back (the last item if you leave i out); .remove(x) removes the first item equal to the value x.

pre-allocation data structures

Making a list with the right number of placeholder slots before filling it — e.g. [None] * 6 — so you can write into a position with my_list[i] = value. You can't assign to a position that doesn't exist yet (that raises an IndexError).

.keys() / .values() / .items() data structures

Dictionary methods for getting at the contents. .keys() gives all the keys, .values() all the values, and .items() the key–value pairs together. .items() is what lets a for loop unpack both at once: for name, params in scenarios.items():. Forget it and you only get the keys, so Python raises "too many values to unpack."

.get() data structures

A dictionary method that looks up a key safely: my_dict.get(key, default) returns the default value (or None if you give none) instead of raising a KeyError when the key is missing.

.update() data structures

A dictionary method that adds new key–value pairs, or overwrites the values of keys that already exist: scenario.update({"rw": 0.5}).

dictionary unpacking (**) data structures

Putting ** before a dictionary in a function call unpacks each key–value pair into a keyword argument: factor_of_safety(**params). It only works when the dictionary's keys exactly match the function's parameter names. You can add one more keyword argument, factor_of_safety(**params, rw=0.5), as long as rw isn't also a key in the dictionary.

nested dictionary (dict of dicts / dict of lists) data structures

A dictionary whose values are themselves dictionaries or lists. Use one key per level to dig in: gully_profiles["Geer-Canyon"]["area_km2"]. Looping through one takes a nested loop — the inner loop walks through whatever the outer loop hands it. A dictionary of lists (one list of results per scenario) is a common way to store the output of a nested loop.

Errors & Debugging
NameError errors

An error raised when Python encounters a name (usually a variable) it doesn't recognize — often a typo, or the variable's cell hasn't been run yet.

ValueError errors

An error raised when a function receives a value of the right type but the wrong content to do what you asked — most often when converting a non-numeric string to a number, e.g. float("Mercury").

IndexError errors

An error raised when you try to access a list index that doesn't exist — most often off-by-one mistakes, or forgetting that indexing starts at 0, e.g. planet_list[10] on a 5-item list.

TypeError errors

An error raised when an operation is applied to a data type it doesn't support — e.g. trying to add a string and an int ("5" + 5), or indexing into something that isn't a list, tuple, or string.

KeyError errors

An error raised when you try to access a dictionary key that doesn't exist using square brackets, e.g. planet_data["Pluto"]. Using .get() instead returns None rather than raising an error.

None / NoneType errors

None is Python's special value representing "nothing here" — it has its own data type, NoneType. Commonly returned by dictionary.get() when a key isn't found, instead of raising a KeyError.

traceback errors

The block of red text Python prints when your code hits an error. Read it from the bottom up — the last line names the error type and gives a short message; the lines above point to where in your code it happened.

shadowing errors

Reusing a variable name so the new one hides the old one — for example using the same loop variable for both an outer and an inner loop. Python raises no error; the outer variable just gets overwritten. Give every loop variable its own descriptive name.

logic error errors

A bug that produces no error message: the code runs fine but gives the wrong answer (an indented line in the wrong place, or a counter that never resets). Catch them by checking results against something you know, such as whether the pieces add up to the total.

tracing (print debugging) errors

Adding print() statements inside a loop to watch what each variable is on every pass. Shrink the problem first (2 items instead of 200) so the output is easy to read.

Math & Notation
LaTeX math & notation

A typesetting language used to write mathematical notation. In a Jupyter markdown cell, LaTeX written between dollar signs renders as a formatted equation — see the Cheat Sheets page for syntax.

inline math / display math math & notation

Inline math (single dollar signs, e.g. $v = d/t$) renders within a line of text. Display math (double dollar signs, e.g. $$v = d/t$$) renders centered on its own line, larger.

summation notation math & notation

Mathematical shorthand (the Greek capital sigma, Σ) for adding up a sequence of terms, e.g. Σxᵢ means "add up all the x values." Written in LaTeX as \sum.

uncertainty notation math & notation

The ± symbol used to express a measurement's margin of error, e.g. 4.2 ± 0.3 cm/yr. Written in LaTeX as \pm.
