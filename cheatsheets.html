The files you see and edit in your folder.
untracked
A file git has never been told to keep. Git ignores it, and won't back it up.

The "about to be committed" list. git add puts a file on it.
commit
A saved snapshot of your staged changes, with a short message. It stays on ExploreHub until you push.
push / pull

origin
Git's nickname for the GitHub repo you cloned from.

One-Time Setup

Do this once. Your ExploreHub account keeps these settings.

1Tell git who you are

Use the email on your GitHub account.

git config --global user.name "Your Name"
git config --global user.email you@vanderbilt.edu

2Set friendly defaults

git config --global pull.rebase false        # pull = merge (avoids a confusing error)
git config --global core.editor nano         # nano instead of Vim when git asks for a message
git config --global init.defaultBranch main  # empty repos start on main
git config --global push.autoSetupRemote true  # first push sets the upstream for you

Check everything with git config --global --list.

Made a typo? Run the same command again with the right value, and it replaces the old one. If you mistyped the setting's name (for example user.ame), remove it with git config --global --unset user.ame. Your name needs quotes because it has a space; your email doesn't.

3Make an SSH key

An SSH key lets ExploreHub prove to GitHub that it's you, without a password. Check first: if ls ~/.ssh shows id_ed25519.pub, skip to step 4.

ssh-keygen -t ed25519 -C you@vanderbilt.edu

Press Enter three times. The fingerprint and the square picture it prints are not your key.

4Give your public key to GitHub

cat ~/.ssh/id_ed25519.pub

Copy the whole line it prints (it starts with ssh-ed25519). In the JupyterLab terminal, copy with Ctrl+Shift+C. On github.com: profile picture → Settings → SSH and GPG keys → New SSH key, title it "ExploreHub", paste, and save.

Only ever share the file ending in .pub. The one without .pub is your private key: never paste it anywhere.

5Test the connection

ssh -T git@github.com

Type yes if asked. Success looks like Hi adasmith! You've successfully authenticated…

Habits That Prevent Most Problems
  • Run git status before and after every command. It tells you where you are, what changed, and whether you're in sync with GitHub.
  • Save, add, commit, push, in that order. Skipping save is the most common reason a "submitted" notebook arrives empty.
  • Pull before you start working in any repo that might have changed on GitHub.
  • Check pwd before git commands. Git acts on whichever repo you're standing in.
  • Code goes in git; big data doesn't. Keep large files (anything over about 50 MB) out of your repos.

pathlib Module

Import with from pathlib import Path — a modern, cross-platform way to work with file paths. Path objects use / to build paths and work correctly on Windows, Mac, and Linux.

A note on capitalization: Path (capital P) is the class — the blueprint you import. path (lowercase p) in the table below is just a placeholder for whatever variable you've stored a Path object in — you could call it p, my_file, or anything else. For example: p = Path('/home/jovyan/data.csv') then p.name. Class names in Python are capitalized by convention; variable names are not.

Errors
ErrorDescriptionCommon cause
NameError Python doesn't recognize a name you've used Typo, or the variable's cell hasn't been run yet
ValueError A function got the right type but a value it can't work with float("Mercury") — can't convert a non-numeric string
IndexError You asked for a list index that doesn't exist planet_list[10] on a 5-item list
TypeError An operation was applied to a data type that doesn't support it "5" + 5 — can't add a string and an int
KeyError You asked for a dictionary key that doesn't exist planet_data["Pluto"] — use .get() to avoid this
Traceback The red error message Python prints — read from the bottom up Last line = error type + message; lines above = where it happened
ValueError: too many values to unpack A loop (or assignment) tried to split each item into more variables than the item holds for key, value in my_dict: — forgot .items()
IndexError: list assignment index out of range You tried to write into a list position that doesn't exist yet fs = [] then fs[0] = 1.2 — use .append(), or make the slots first with [None] * n
TypeError: ... 'NoneType' You tried to do math with None (a missing value) total += None — check for it with if value is None: and use continue
Infinite loop Not an error message: the cell just keeps running A while loop with no update line — click ■ to interrupt the kernel, then clear the output
Logic error (no message) The code runs without complaint but gives the wrong answer A running total that never resets, or a line indented at the wrong level — shrink the problem and print the loop variables
